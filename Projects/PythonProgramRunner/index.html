¿Cómo funciona esto?

Pyodide es una build de CPython (el intérprete normal de Python) compilada a WebAssembly. Al cargarla, el navegador descarga un intérprete de Python completo y lo corre dentro de la misma pestaña — no hay ningún servidor ejecutando tu código, todo pasa en tu máquina.

Estructura de archivos

tu-proyecto/
├── index.html
├── style.css
├── runner.js
├── pyodide/            <- runtime de Pyodide (WASM + stdlib de Python)
└── program/
    ├── manifest.json   <- qué archivos .py cargar y cuál es el de entrada
    └── main.py         <- tu programa, un script normal e independiente

Lo que hace runner.js, en orden

  1. Carga Pyodide con loadPyodide().
  2. Redirige la salida de Python hacia la consola con pyodide.setStdout() / setStderr().
  3. Descarga los archivos listados en manifest.json y los escribe en el sistema de archivos virtual de Pyodide con pyodide.FS.writeFile().
  4. Ejecuta el archivo de entrada leyéndolo con open() y corriéndolo con exec(), tal como lo haría un intérprete real desde la terminal.

El truco para que input() bloquee de verdad

Normalmente en un navegador no puedes "congelar" la ejecución a mitad de camino a esperar que el usuario escriba algo, sin recurrir a Web Workers. Esta build de Pyodide soporta JS Promise Integration (JSPI), una función experimental de WebAssembly que sí lo permite:

  • El programa se ejecuta llamando a una función Python async con .callPromising() en vez de esperarla normalmente.
  • Dentro de esa función, pyodide.ffi.run_sync(promesa) pausa la pila de Python hasta que una Promise de JavaScript se resuelve, sin trabar el navegador.
  • Se reemplaza builtins.input por una versión que usa run_sync sobre una función de JS que muestra el prompt, habilita el campo de texto y resuelve la promesa cuando el usuario presiona Enter.
Ver el patrón mínimo en código 
// JS: función que espera al usuario
function getUserInput(prompt) {
    return new Promise((resolve) => {
        mostrarPrompt(prompt);
        onEnterPresionado = (texto) => resolve(texto);
    });
}
pyodide.globals.set("__js_get_input", getUserInput);

// Python: input() reemplazado, usando run_sync
pyodide.runPython(`
async def correr(archivo):
    from pyodide.ffi import run_sync
    import builtins

    def mi_input(prompt=""):
        return run_sync(__js_get_input(prompt))

    builtins.input = mi_input
    exec(open(archivo).read())
`);

// Se necesita callPromising() para habilitar JSPI en esa llamada
await pyodide.globals.get("correr").callPromising("main.py");

¿Cómo cargo mi propio programa?

  • Reemplaza program/main.py por tu script.
  • Si usas varios archivos .py, agrégalos a la lista "files" de manifest.json (se importan entre sí con normalidad).
  • No hace falta tocar runner.js para esto.

Requisitos

JSPI es una función relativamente nueva de WebAssembly; funciona en versiones recientes de Chrome y Edge. Si el navegador no la soporta, runner.js lo detecta y muestra un mensaje de error explicándolo en la consola de la página. El aviso de "SharedArrayBuffer" que a veces aparece en la consola de desarrollador del navegador es solo una advertencia interna de Pyodide y no afecta el funcionamiento.
